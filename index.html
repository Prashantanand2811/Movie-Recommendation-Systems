SYSTEM COMPONENTS

How It Works

01 / INGESTION
Event Streaming
User clicks, views, ratings published to Kafka at 500+ events/sec. Each event includes user ID, movie ID, event type, rating, session context, and UTC timestamp.
KafkaJSON events1M+ dailygzip
02 / FEATURES
Stream Processing
Spark Structured Streaming consumes Kafka events, computes 10-minute rolling window features per user: genre affinity, interaction frequency, session depth, avg rating.
PySparkRedis10-min windowsTTL 1hr
03 / MODELLING
Hybrid Ranking
SVD (k=12) learns latent user/item factors for collaborative scoring. TF-IDF on movie overviews + binary genre vectors power content similarity. Cold-start handled via content reweighting.
SVDTF-IDFNDCG@10: 0.94Cold-start
04 / SERVING
Low-Latency API
FastAPI serves recommendations via ONNX Runtime. Pre-computed embeddings cached in memory; live user features fetched from Redis per request. 4 async workers for throughput.
FastAPIONNX Runtime<100ms p954 workers
05 / MLOPS
Automated Retraining
Kubeflow Pipelines trigger retraining when drift is detected in embedding distributions or genre interaction shifts. CI/CD deploys new ONNX artifacts in under 5 minutes.
KubeflowCI/CD<5 min deploy↓80% effort
06 / EVALUATION
Offline + Online Metrics
Offline: NDCG@K, Recall@K, Precision@K via leave-one-out split. Online: p95 latency, throughput, recommendation freshness. Drift detection on embedding distributions.
